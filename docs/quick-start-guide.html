GAME UI DESIGN COPILOT · USER MANUAL

使用说明书 v0.2.2

面向游戏 UI 设计师的 AI 设计流水线：从一张 UE 线框稿，走到一张可交付、全程可追溯的 UI 成图。

这是什么工具？

你把一张 UE 线框稿 + 一段设计意图交给它，AI 会沿着一条流水线逐步产出：功能契约 → 布局 → 风格规范 → 组件绑定 → 底图 → 最终成图。每一步的产出（Artifact）都由你人工检查并批准，AI 不会替你拍板；每次批准都留有版本与证据，随时可以回看、回退、重新生成。

它擅长

  • 读懂 UE 线框稿，整理出页面功能契约
  • 给出可比较的布局提案与可复现的风格规范
  • 延续已有游戏的 UI 风格（严格继承模式）
  • 用你提供的真实组件切图与字体合成最终 PNG

它不做

  • 不替你批准任何产物——批准权永远在人
  • 不允许手改生成的 JSON/PNG——产物是只读证据
  • 不跳过流程——按钮置灰就是前置没完成，这是设计

一、安装与启动

前提：电脑已安装 Node.js 与 pnpm（终端输入 node -v、pnpm -v 能看到版本号即可）。

方式一（推荐）：双击项目根目录的 Start Game UI Design Copilot.command，会自动安装依赖并启动。

方式二：终端进入项目目录运行 pnpm quick-start。

方式三（开发模式）：

pnpm install
pnpm dev

二、配置 AI 连接（只需做一次）

工具通过 Kunpo 调用模型。推荐在项目根目录 .env 里指向本地 Gateway：

KUNPO_GATEWAY_BASE_URL=http://127.0.0.1:9020/v1

配置好后看窗口顶栏右侧：出现 Gateway 已就绪 说明连接成功；显示 Kunpo 未配置 则检查 .env 拼写后重启工具。

模型名称可在顶栏 ⚙ 设置（模型与工作区配置）里修改：视觉理解模型、图像模型两项自由填写，保存后新任务立即生效。

⚠️ 真实 API Key 只保存在 .env 或 Gateway 服务端，永远不要提交到代码仓库。

四、第一次使用：最短走通路径

  1. 建立项目 — 首次打开会自动弹出创建窗口（也可以点顶栏 ＋ 新项目）。填项目名称，选择「新项目」或「已有项目」，点「创建并进入工作台」。项目文件默认保存在 ~/Game UI Design Projects。
  2. 00 输入 — 在右侧「UE WIREFRAME」卡片点 选择图片 导入线框稿；设计意图可以留空，点 AI 解读并预填写 让 AI 先读 UE 生成草稿，检查后点 确认意图并开始功能解读。
  3. 01 功能解读 — 等 AI 生成功能契约，快速浏览四类信息（必需控件 / 必要信息 / 交互状态 / 边界情况），逐类进入检查、按需修改，然后点 批准功能契约。
  4. 沿界面按钮往下走 — 每个阶段底部都有下一步按钮（如「生成布局提案」「进入风格锁定」）。按钮置灰不是故障，照着旁边的灰字提示回上游补齐即可。
  5. 随时看证据 — 点顶栏检查器图标，可以看到每个产物的版本、来源和 JSON；任何不确定的地方都可以回看。
  6. 导出成图 — 新项目走到「04 视觉探索」批准方向后导出 PNG；已有项目（严格继承）走到「STRICT PRODUCTION」面板完成保真校验后 导出最终 PNG。两条链路的完整步骤见「两条使用链路」页签。
💡 核心原则：只按界面提供的按钮从上到下操作。不要手动改项目目录里的 JSON/PNG 文件（生成产物是只读证据，手改会报错）；任何不确定的状态，从上游重新生成永远比手工修补安全。

先选链路：这个项目是「从零探索」还是「延续已有风格」？

创建项目时的选择决定整条流水线的走法。两条链路的阶段相同，但顺序和门禁不同——创建时选错也没关系：已有项目可以随时在「00 输入」里切换继承强度（见下文），新项目则建议直接重建。

你的情况创建时选择走哪条链路
全新玩法/新界面，视觉风格可以自由探索新项目链路 A · 探索链路：先布局，再锁风格，最后生成 3 个视觉方向供评审
游戏已有成型 UI，新界面必须「看起来像同一个游戏」已有项目 → 严格继承（推荐）链路 B · 严格继承链路：先参考图锁风格，导入真实字体/组件并绑定，再出布局、底图、合成、保真校验
有既有风格参考，但想保留一定探索空间已有项目 → 引导继承链路 B 的宽松版：同样导入参考与资产，但不强制完整 strict 门禁

链路 A · 新项目探索链路

流程总览

00 输入需求+线框→ 01 功能契约批准→ 02 布局三选一→ 03 风格生成并锁定→ 04 生成 3 个视觉方向→ 评审批准 · 导出 PNG
  1. 00 输入：导入 UE 线框稿 → AI 预填设计意图 → 检查/补充后「确认意图并开始功能解读」。美术大方向选填（如「克制东方奇幻」），会影响后续风格与视觉生成。
  2. 01 功能解读：检查功能契约（四类关键信息），点「批准功能契约」→「生成布局提案」。
  3. 02 布局设计：AI 给出 3 套布局提案，比较区域比例、焦点路径与信息承载，选一套批准。不满意可「重新生成」。
  4. 03 风格锁定：点底部「进入风格锁定」，AI 依据布局与美术方向生成 Style Contract（语义色彩、字体规则、材质、几何、光影、构图）。可以导入参考图辅助，也可以不导入。核对可执行数值后点「批准并锁定」。
  5. 04 视觉探索：点「生成 3 个方向」，AI 逐张产出 保守继承 / 表现强化 / 局部创新 三个方向。可全屏检查、多选组合、写评审批注、单张重试。
  6. 交付：选 1 个方向点「批准所选方向」（选 2 个以上可「组合所选」）；点卡片上的导出按钮即可导出单张 PNG。

链路 B · 已有项目严格继承链路

流程总览

00 输入→ 01 功能契约→ 03 参考图+风格锁定→ 字体+组件+绑定→ 02 组件感知布局→ 底图生成+污染审查→ 合成+保真+导出

注意：严格链路的推荐执行顺序是 00 → 01 → 03 → 02 → 04（先锁风格资产，再出布局）。不必记顺序——每一步完成后界面会给出下一步按钮。

开工前备好素材：

  • ≥1 张既有 UI 截图（PNG/JPG，越接近目标屏幕越好）
  • 既有 UI 使用的 OTF/TTF 字体文件
  • 组件切图：按钮/导航/页签等控件的各状态 PNG（strict 要求 button/navigation/tab 具备 disabled 与 pressed/selected 状态）
  1. 创建项目：选「已有项目」，继承强度保持「严格继承（推荐）」。创建后项目进入 strict 门禁体系。
  2. 00 输入：与链路 A 相同——导入线框稿、确认设计意图。
  3. 01 功能解读：校对并「批准功能契约」。注意：strict 模式下所有「必需控件」后续都要绑定组件，清单要覆盖需求中的全部元素。
  4. 03 风格锁定 · 参考图：进入风格锁定阶段，先导入既有 UI 截图，逐张批准至少 1 张，然后点「解析视觉风格」。生成的 Style Contract 必须全部是可执行值（hex 颜色、具体字号），看到模糊词就重新生成。
  5. 批准并锁定风格：核对后点「批准并锁定」，下方出现「STRICT CONTINUATION · 严格继承资产与绑定」面板，顶部四个门禁：风格规范 / 字体清单 / 组件契约 / 控件绑定。
  6. 导入字体：填写字体 ID 与覆盖范围，勾选使用权与精确匹配承诺，「选择字体」导入文件；然后为每个语义角色（display、body、numeric、button-label、tab-label…）执行「确认」；最后「批准字体清单」。导入 ≠ 确认：身份关键角色必须 exact 确认，否则最终合成会被拦下。
  7. 导入组件：逐个 family 填写组件 ID、类别、状态、复用策略（exact / nine-slice / vector-token / reference-locked）、文字策略，「选择切图」导入；九宫格组件在「9-Slice 边距」填四个方向的像素值；也可用 Forge Manifest 批量导入。全部导入后「批准组件契约」。
  8. 控件绑定：为每个必需控件显式选择 组件 → 状态 → 字体角色。语义不兼容的选项会灰显并标注原因；没有任何隐式默认，必须全部显式选完才能「保存绑定」→「批准」。
  9. 生成组件感知布局：四个门禁全部批准后按钮解锁，生成布局 → 到「02 布局设计」选择方案并批准。
  10. 底图链路：布局批准后点「建立底层规范」（自动生成 Underlay Contract + 结构 Guide），再点「生成底层图」产出 3 张底图。
  11. 04 严格生产：进入视觉探索阶段下方的「STRICT PRODUCTION」面板：「自动污染审查」→ 不合格就「修复并复审」（次数有限）或填 ≥10 字符理由 waiver 放行 → 「合成预览」检查水印 → 「加载字体并生成最终 PNG」→ 「保真校验」→「最终批准」→「导出最终 PNG」。

引导继承（existing-guided）是什么？

已有项目的宽松模式：同样建议导入参考图与资产，但不强制 strict 的完整门禁（证据强制、语义校验、哈希一致）。适合「风格大致延续、允许 AI 发挥」的场景。

两种强度可以在「00 输入」阶段的「继承强度」下拉里随时切换；切换会按依赖图让模式相关的下游批准失效，需要重新批准。已锁定的项目（locked-continuation）不可再切换。

两条链路对比速查

链路 A · 新项目探索链路 B · 严格继承
参考图可选必须 ≥1 张并批准
字体 / 组件切图不需要必须导入并确认（exact、完整状态集）
控件绑定不需要必需控件 100% 显式绑定 + 语义门禁
布局生成时机功能契约批准后立即生成风格、字体、组件、绑定全批准后生成（组件感知）
视觉产出3 个 AI 生图方向（探索）3 张结构底图 + 确定性合成最终 PNG
交付门禁人工评审批准方向污染审查 + 保真校验（13 项）+ 哈希再检

五个阶段逐一拆解

左侧「DESIGN FLOW」的 5 个节点就是这 5 个阶段。节点上的彩色状态点表示进度；阶段内所有操作都在主工作区完成，阶段底部始终有「下一步」按钮。

00 · 项目输入线框稿、设计意图、继承强度 01 · 功能解读功能页面契约四类信息 02 · 布局设计布局提案比较与批准 03 · 风格锁定参考、风格、字体、组件、绑定 04 · 视觉探索视觉方向 / 底图、合成、保真
00 · INPUT

项目输入

目标：让 AI 读懂 UE 线框稿，并由你确认设计意图。

操作步骤

  1. 导入线框稿：右侧「UE WIREFRAME」卡片点 选择图片（导入后可点「放大对照」全屏查看，之后可用「替换」换图）。没导入线框稿时，后面所有按钮都是置灰的。
  2. 设计意图：可以留空。点 AI 解读并预填写，AI 只推断画面中可见的页面目标与流程，生成一份可编辑草稿；隐藏玩法规则由你补充。检查后点 确认意图并开始功能解读（确认后仍可修改再「重新生成功能契约」）。
  3. 美术大方向（选填）：一句话风格基调，用于后续风格锁定与视觉探索，不影响功能识别。
  4. 继承强度（仅已有项目）：严格继承（推荐）/ 引导继承。切换会让模式相关的下游批准失效；锁定继承的项目不可切换。

页面栏（多页面管理）

顶栏下方的页面栏管理本项目的多个页面（Screen）：下拉切换当前页面、重命名、＋ 新建独立页面、复制当前页面（含全部产物）、归档其他页面。每个页面独立拥有一套线框稿、需求、功能契约、布局与绑定；而风格规范、字体、组件、参考图是项目级共享的。

01 · UNDERSTAND

功能解读

目标：校对 AI 生成的功能页面契约（Screen Contract）并批准。

界面结构

  • 契约总览：页面名称、页面目的、核心动作；「UE 来源覆盖校验」会确认线框稿里的功能没有遗漏。
  • 四类关键信息卡片：必需控件 / 必要信息 / 交互状态 / 边界情况，每张卡显示检查进度（x/y 已检查）。点卡片进入「专注检查」工作台。

专注检查里能做什么

  • 对每一条标记：已确认 / 有疑问；也可以直接编辑或删除条目、新增条目；支持搜索与按状态筛选。
  • 编辑「必需控件」时必须给出稳定 ID（小写字母+连字符，如 confirm-purchase）和语义角色（从受控词表中选择，不能是泛化的 action）。角色决定后面能绑定哪类组件。
  • 所有修改先停留在本轮草稿里，点 保存本轮修改 统一生成一个新版本；关闭时如有未保存修改会弹出确认。

底部按钮

重新解读（输入变了会提示「输入已变化，重新解读」）· 批准功能契约 · 批准后变为 生成布局提案。

02 · STRUCTURE

布局设计

目标：从布局提案中比较、调整并批准一套 Approved Layout。

操作要点

  • AI 基于功能契约生成布局提案（新项目 3 套；严格链路生成「组件感知布局」）。在目标分辨率里检查区域比例、焦点路径、安全区与实际信息承载。
  • 选择方案并批准；不满意点「重新生成」。
  • 上游（画布/需求/契约）变化后布局会标记「需更新」，旧布局只能用于对照——按提示先更新功能契约。
  • 批准后的下一步按钮随链路变化：新项目显示「进入风格锁定」；严格链路且风格已批准时显示「建立底层规范」（自动生成 Underlay Contract + 结构 Guide），随后是「生成底层图」。
03 · STYLE LOCK

风格锁定

目标：把美术方向沉淀成可复现的视觉规范（Style Contract），严格链路还要在这里完成字体、组件与绑定。

① 参考图（已有项目必需）

  • 导入既有 UI 截图（可多张），逐张批准或拒绝；已有项目必须至少批准 1 张才能解析风格。
  • 若系统提示「确认省略项并继续」，表示有未处理的参考图，按提示确认即可。

② 解析并锁定风格

  • 点 解析视觉风格（前置条件不满足时按钮旁的灰字会说明缺什么：严格链路需功能契约已批准；新项目需布局已批准）。
  • 生成的规范展示：视觉识别、语义色彩系统（可复制的色块与 hex）、材质/几何/光影/组件/构图规则。点「编辑规范」可以直接改 JSON，保存生成新版本。
  • 核对无误后点 批准并锁定。

③ STRICT CONTINUATION 面板（仅严格链路，风格批准后出现）

  • 字体：填字体 ID、覆盖范围（如 latin），勾选「有权使用」与「精确匹配」，选择 OTF/TTF 导入；再为每个语义角色填入角色名并「确认」；最后「批准字体清单」。身份关键角色（display/body）必须 exact 确认。
  • 组件：每个组件填写 组件 ID、类别、状态、复用策略、文字策略（文字层/无文字）、最大缩放，选择切图导入。九宫格组件选 nine-slice 并填边距（左,右,上,下）。也支持 Forge Manifest 导入。全部完成后「批准组件契约」。
  • 控件绑定：为功能契约里的每个必需控件依次选择：组件（不兼容项灰显并说明原因）→ 状态（必选）→ 字体角色（按控件角色必选或可选）。全部显式选完 →「保存绑定」→「批准」。编辑绑定会清除旧批准，需重新批准。
  • 四个门禁全绿后，点 生成组件感知布局，转入 02 布局设计批准。
04 · EXPLORE

视觉探索

目标：产出并评审视觉结果，完成交付。这个阶段的内容随链路不同：

链路 A · 视觉方向评审

  • 风格批准后点「生成 3 个方向」，产出 保守继承 / 表现强化 / 局部创新 三张方向图（逐张写入，可随时「停止剩余任务」，已完成的不丢）。
  • 每张卡片可：全屏检查、勾选加入评审、「仅重试此方向」；下方可写评审批注（会成为下一轮生成的反馈）。
  • 选 1 个 →「批准所选方向」；选 ≥2 个 →「组合所选」；都不满意 →「全部否决并重探」（批注会带进下一轮）。
  • 批准后在卡片或全屏里导出 PNG。

链路 B · STRICT PRODUCTION 面板

底图生成后，阶段下方出现严格生产面板，顶部三个门禁：污染审查 / 最终 PNG / 保真校验。按顺序操作：

  1. 自动污染审查：AI 审查底图是否出现文字状、UI 状纹理等污染，输出证据与问题清单（可展开查看）。
  2. 未通过时二选一：修复并复审（自动修复，有次数上限）；或确认问题可接受，填写 ≥10 字符 的理由做 waiver（留痕的人工决策，不是绕过）。
  3. 合成预览：确定性合成预览，检查结构与文字位置。若预览上有「TYPOGRAPHY PREVIEW」水印，说明存在未 exact 确认的文字图层，回 03 完成字体确认后重新合成。
  4. 加载字体并生成最终 PNG：实际加载字体文件渲染最终图。
  5. 保真校验：运行 Fidelity 检查；有 blocker/critical 必须回上游修复，major 可逐条批准。
  6. 最终批准 → 导出最终 PNG（导出时会再次校验哈希，防止输出被外部改动）。

Artifact（产物）与项目目录

流水线每一步的输出都是一个 Artifact（如 screen-contract.json、approved-layout.json、composition-manifest.json），带有 schema_version / id / version / status / source 五项元信息，全程可追溯。项目默认保存在 ~/Game UI Design Projects，结构为：

项目目录/
├── project.json          # 项目主文件
├── screens/              # 每个页面一套：输入、契约、布局、绑定、底图、合成…
│   └── main/
├── style/                # 项目级共享：风格契约、字体清单、组件契约、参考图、切图
└── workflow/             # 流水线状态与产物历史（只读，勿手改）

复制整个项目目录 = 一份完整备份。任何重大操作前都可以先复制一份。

Stale（需更新）传播机制

改了上游，所有受影响的下游产物会自动标记「需更新」，防止旧批准被误用。触发条件举例：改控件的 id / role / required、换参考图重新解析风格、重新生成布局、编辑绑定……

恢复方法：从变更点开始，按依赖顺序重新生成、重新批准。例外：只改控件的显示名（label）不会触发 stale。

🚫 不要试图手工删除 stale 标记或编辑产物 JSON——生成产物只读，手改会直接报错（GENERATED_EVIDENCE_READ_ONLY），唯一解除方式是重新生成。

门禁与证据链（严格链路）

strict 模式的每个批准都依赖可复验的证据而非模型自述：图像证据（底图/审查 overlay/组件板落盘并记 sha256）、语义证据（模型审查原始响应落盘）、像素证据（Fidelity 实时解码输出 PNG 计算摘要）、引用一致（manifest ↔ output ↔ fidelity-report 三层互相引用，任何一层漂移都会被拦下）。

这就是为什么严格链路按钮置灰特别多——每一个置灰都是缺某项证据，照提示补齐即可，不存在「绕过」的入口。

两条铁律

  • 生成产物只读：手改 Artifact JSON/PNG 会直接报错，唯一恢复方式是重新生成。
  • 重新生成 > 手工修补：任何不确定的状态，从最上游重新生成永远比手改安全；复制项目目录永远是你的后悔药。

遇到问题先对号入座

流程与按钮

流程按钮置灰 / 提示「xxx is required」？
不是故障，是流程顺序问题。按钮旁的灰字会说明缺什么，回上游工作台补齐对应批准即可。
stale下游全变「需更新」了？
说明你改了上游。从最上游变更点开始按依赖顺序重新生成、重新批准。若只改了控件显示名仍 stale，检查是否同时动了 id / role / required。
流程切换继承强度后很多批准失效？
这是预期行为：strict ↔ guided 切换会按依赖图使模式相关的下游批准失效，按提示重新批准即可。已锁定（locked-continuation）的项目不可切换。
流程strict 下提示 UNDERLAY_SPEC_REQUIRED？
缺 Layout Guide 就生成底图会被拦截——strict 无捷径。回 02 布局阶段点「建立底层规范」（Underlay Contract + Guide），再生成底图。

资产与门禁

字体字体导入后还要点什么？
导入 ≠ 确认。必须逐项确认 license（可再分发）与 exact（与目标字体完全一致）；字体角色不能直接编辑，只能走「重新导入 + 确认」。身份关键角色缺 exact 确认，最终合成会被拦下。
合成preview 合成图上有水印？
存在未 exact 确认的文字图层。去 03 字体区完成 exact 确认后重新合成，水印即消失。
绑定绑定批准报 BINDING_* 错误？
按违规明细修正绑定（角色词表、状态匹配、文字策略）后重新校验批准。注意：编辑绑定会自动清除旧批准，需要重新批准。不兼容选项会灰显并标注原因，优先选非灰选项。
审查Underlay 污染审查一直 blocking？
先「修复并复审」；达到修复次数上限（UNDERLAY_REPAIR_LIMIT）后，调整上游（布局 slot、视觉 prompt）重新生成底图；确认可接受则填写 ≥10 字符的 waiver 理由放行。
保真Fidelity 门禁失败（FIDELITY_GATE_FAILED）？
重跑保真校验生成新报告；blocker / critical 必须回上游修复后重新生成；major 可人工逐条批准。若报 FIDELITY_EVIDENCE_STALE，通常是批准前项目文件被外部动过，重跑 fidelity 即可。
导出导出按钮不可用 / 导出报哈希错误？
导出要求最终合成完成且保真校验通过（严格链路还需最终批准）。FINAL_EXPORT_HASH_MISMATCH 表示输出文件被外部改动，重新合成后再导出。

连接与运行

连接顶栏显示「Kunpo 未配置」？
检查项目根目录 .env 的 KUNPO_GATEWAY_BASE_URL（推荐 http://127.0.0.1:9020/v1），保存后重启工具。配置查找顺序：DESIGN_COPILOT_ENV_FILE 指定的文件 → 项目 .env。
连接AI 生成超时 / 鉴权失败？
检查 .env 与设置里的模型名（模型名必须受服务端支持）。临时失败不会丢已完成的证据链，点错误条上的「重试」即可。详见 docs/dev/PROVIDER-TROUBLESHOOTING.md。
运行生图进行中想停？
视觉探索生成时可以点「停止剩余任务」；已写入的图片不会丢，之后可「补全缺失方向」。
运行想看完整错误码含义？
全部错误码见 docs/dev/ERROR-CATALOG.md（与代码注册表双向校验）；失败恢复路径见 docs/user/FAILURE-RECOVERY.md。

兜底三原则

  1. 复制整个项目目录 = 完整快照备份，重大操作前先备份；
  2. 任何不确定的状态，从最上游重新生成永远比手工修补安全；
  3. 证据都在：产物检查器 + workflow/ 历史可以回答「这一步到底发生了什么」。
