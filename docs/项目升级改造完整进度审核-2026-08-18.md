## 3. Golden 阈值存在过拟合风险

报告显示，真实样例运行中不断调整：

- BBox 归一化；
- 主体定义；
- `subject_overlap_confidence`；
- 语义繁忙度与像素指标融合；
- 字体颜色；
- Provider URL 处理。

这些调整本身是正常的真实测试反馈，但存在一个风险：

> 使用同一组三个 Golden Sample 调阈值，再使用同一组三个样本证明阈值正确。

这会导致测试集与开发集混用。

建议改为：

```
校准集：当前 3 组 Golden
验收保留集：另外至少 2 组未参与阈值调整的样本
```

流程必须是：

1. 在校准集上完成阈值调整；
2. 固定 `threshold_version`；
3. 不再改代码；
4. 对保留集执行；
5. 保留集失败时，改代码后必须重新跑全部校准集和保留集。

否则即使 3/3 通过，也不能充分证明对新页面具有泛化能力。
